# Road to Embedded V2 — 面向工程实践的交互式学习系统

## 为什么升级

嵌入式资料并不稀缺。真正困难的是：初学者如何保持兴趣、形成理解，并把知识迁移到真实工程。

因此本项目不再把“写完整教程”作为主要目标，而是把学习过程设计成一系列可参与、可观察、可挑战、可复盘的工程任务。

核心理念：

> 少一点被动阅读，多一点现象、问题、操作、反馈和成就感。

## 三层内容体系

### Layer 1：Knowledge Base — 知识底稿

Markdown 保留，但角色发生变化。

它负责：

- 保证知识准确；
- 给出概念边界；
- 作为查询手册；
- 为 AI / OpenMAIC 生成互动课程提供可靠输入；
- 学习后用于复习。

它不再承担“必须从头读到尾”的责任。

### Layer 2：Interactive Lesson — 互动课堂

每个核心知识点尽可能转换为 15～40 分钟的互动学习单元。

推荐结构：

```text
工程现象 / 故事
    ↓
提出问题
    ↓
先猜答案
    ↓
可视化 / 动画 / HTML 模拟
    ↓
AI 教师解释
    ↓
立即操作
    ↓
故意制造错误
    ↓
观察现象
    ↓
定位原因
    ↓
一分钟总结
```

OpenMAIC 可作为主要互动课堂载体之一，利用 Slides、Quiz、HTML Simulation、AI Agents、PBL 等能力。

### Layer 3：Engineering Lab — 工程实验

最终必须离开课件，进入代码和真实硬件。

```text
PC 模拟实验
→ MCU 开发板实验
→ 仪器观察
→ 故障注入
→ 独立排查
→ 综合项目
```

## 一节课不再以“章节”为中心

传统形式：

> 第 3 章：C 语言位运算

新的形式：

> 挑战：只改变 GPIO 的第 5 位，为什么其他 LED 也灭了？

知识点隐藏在问题后面。

学习者首先看到的是现象和目标，然后为了完成任务主动获取知识。

## 标准互动课程模板

每一课尽量包含以下模块，但不要求机械全部出现。

### 1. Hook — 先让人产生疑问

控制在 1～3 分钟。

可以使用：

- 一个异常现象；
- 一个工程任务；
- 一张硬件图；
- 一个错误波形；
- 一段无法解释的代码；
- 一个选择题。

### 2. Mental Model — 建立直觉模型

优先使用图、动画、交互，而不是长篇定义。

例如指针：

```text
变量 → 房间
地址 → 门牌号
指针 → 保存门牌号的纸条
*p → 根据门牌号进入房间
```

类比建立直觉后，再回到准确的工程定义。

### 3. Play — 让学习者操作

例如寄存器模拟器：

- 点击 bit0～bit31；
- 实时显示二进制；
- 实时显示十六进制；
- 显示对应 C 位运算；
- 模拟 LED / Relay 状态。

### 4. Predict — 操作前先预测

例如：

```c
reg |= (1U << 5);
```

先问：执行以后哪些 bit 会变化？

学习者做出预测后再运行。

### 5. Break It — 故意弄坏

每节课至少设计一个典型错误。

例如：

```c
reg = (1U << 5);
```

代替：

```c
reg |= (1U << 5);
```

让学习者观察为什么其他 bit 消失。

### 6. Debug — 像工程师一样排查

不给立即答案。

按照：

```text
现象 → 假设 → 证据 → 排除 → 根因 → 修复 → 验证
```

完成一次小型故障定位。

### 7. Boss Challenge — 小型关卡

将本课知识放进一个稍复杂的问题，不给完整步骤。

### 8. Cheat Sheet — 一页复习

最后只保留真正需要记忆的核心内容。

## 学习节奏

推荐单次学习控制在 25～45 分钟：

```text
5 min   情境 + 问题
10 min  互动理解
10 min  动手实验
5 min   故障挑战
5 min   总结 / Quiz
```

复杂内容拆成多个小关卡，而不是一篇超长文章。

## 游戏化，但不娱乐化

本项目追求“寓教于乐”，但不能把学习变成无意义的积分游戏。

真正的奖励应该来自能力增长：

- 第一次控制 LED；
- 第一次看懂寄存器；
- 第一次用示波器看到 PWM；
- 第一次独立定位 UART 波特率错误；
- 第一次找到 HardFault 根因；
- 第一次让 MCU 和 FPGA 正确通信。

可以使用：

- Stage；
- Mission；
- Challenge；
- Boss；
- Achievement；

但每个成就必须对应真实工程能力。

## 学习者不应该只是“看懂”

能力分为五级：

```text
L1 见过：知道这个词
L2 理解：能解释它解决什么问题
L3 操作：能跟着完成实验
L4 排错：东西坏了能定位
L5 迁移：换芯片/项目仍能使用这个知识
```

Road to Embedded 的核心目标是逐步达到 L4～L5。

## AI 的角色

AI 不只是回答问题。

可以分别扮演：

- 教师：根据学习者水平解释；
- 提问者：通过追问确认是否真正理解；
- 同伴：一起讨论方案；
- 面试官：检查知识掌握；
- 故障制造者：给系统注入问题；
- 调试教练：只给逐级提示，不直接公布答案；
- 项目负责人：提出需求并检查交付物。

## OpenMAIC 的角色

OpenMAIC 不是本项目唯一依赖，而是一种互动内容运行环境。

仓库保存可迁移的课程源材料，OpenMAIC 用于生成或运行：

- Slides；
- Quiz；
- HTML 互动模拟；
- AI 多角色课堂；
- PBL 项目。

即使未来更换平台，核心课程设计仍然保留在仓库中。

## 最终学习闭环

```text
产生兴趣
   ↓
观察现象
   ↓
提出问题
   ↓
建立模型
   ↓
互动验证
   ↓
真实实验
   ↓
故障注入
   ↓
独立定位
   ↓
工程项目
   ↓
复盘沉淀
   ↓
进入下一关
```

这就是 Road to Embedded V2 的核心教学模型。
