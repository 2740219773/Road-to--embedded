# Road to Embedded

> 从基础知识、MCU、RTOS、嵌入式 Linux 到 FPGA，构建一套面向真实工程实践的嵌入式学习与成长体系。

## 项目定位

这个仓库不是单纯的资料收藏夹，也不是只面向某一种开发板或芯片的教程。

目标是建立一条可以长期迭代的学习主线：

**学知识 → 做实验 → 遇到问题 → 定位问题 → 总结经验 → 进入真实工程。**

适合：

- 想从零建立嵌入式知识体系的人；
- 已有软件开发经验，希望向底层系统方向扩展的人；
- 希望从 MCU 逐步走向 RTOS、Linux、FPGA 的工程师；
- 希望把零散知识转化为真实调试和工程能力的人。

## 总体路线

当前主线：

`C → 计算机与电子基础 → MCU → STM32 → 外设 → 中断/DMA → 通信协议 → FreeRTOS → 调试能力 → Embedded Linux → FPGA`

FPGA 会从早期开始保留基础知识入口，但前期不会与 MCU 主线同时深入。先建立 MCU 和嵌入式系统的完整工程认知，再逐步进入数字逻辑、Verilog 和 FPGA 工程。

## 学习原则

1. **先建立地图，再钻细节。** 先知道一个知识点在整个系统里的位置和作用。
2. **每个知识点必须落到实验。** 不以“看懂”为完成标准，以“能自己验证”为标准。
3. **重视调试能力。** 会写代码只是第一步，真正的工程能力来自定位问题。
4. **记录失败案例。** 错误现象、分析过程、最终原因和验证方法都要沉淀下来。
5. **以项目串联知识。** 后期逐渐减少孤立练习，增加跨模块综合项目。
6. **不过度追求一次学全。** 先掌握主干，再根据项目需要补充细节。

## 最终目标

最终希望具备从上层软件到底层硬件的系统理解能力，能够完成或参与：

- MCU 固件开发；
- 常见外设与通信接口开发；
- RTOS 多任务系统开发；
- 嵌入式 Linux 应用与驱动开发；
- FPGA 基础逻辑与接口开发；
- 上下位机联调；
- 示波器、逻辑分析仪、JTAG 等工具辅助调试；
- 从“出现异常”到“定位根因”的完整问题分析。
