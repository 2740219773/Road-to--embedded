# Beginner Readability Standard

Road to Embedded 面向真正的初学者时，不能假设读者已经知道技术名词。

## 新技术词第一次出现时的标准顺序

### 1. 先说它是什么

用一句不依赖其他专业词的话解释。

### 2. 说它在哪儿

例如它在 MCU 内部、引脚外部、PC 端还是协议层。

### 3. 说为什么需要它

从问题出发，而不是从定义出发。

### 4. 给一个直觉类比

类比只用于建立第一印象，随后必须回到准确技术含义。

### 5. 再给正式名称和缩写

避免第一句话就是一串英文缩写。

### 6. 给最小图

优先使用 3～6 个节点的小图说明数据流或控制流。

## 示例

不推荐：

> DMA 使用 Peripheral Request 将数据搬运到 Memory，并通过 TC IRQ 通知 CPU。

推荐：

> DMA 可以先理解成 MCU 里的硬件搬运工。UART 或 ADC 产生很多数据时，CPU 不必一个一个亲自搬进 RAM。CPU 只需要告诉 DMA 从哪里搬、搬到哪里、搬多少个。正式名称是 Direct Memory Access。

然后再介绍 Request、Transfer Complete、Circular Mode 等术语。

## 页面自检

每写完一页，假设读者只学过前一个 Stage，检查：

- 标题中的缩写是否解释？
- 第一段是否用了尚未定义的专业词？
- 新手能否画出这个东西在系统中的位置？
- 新手能否用一句自己的话说明它解决什么问题？
- 是否把进阶内容明确标记为“暂时知道即可”？
- 是否存在可以改成图/互动而不是继续加文字的部分？

## 目标

不是把技术内容变浅，而是把进入技术内容的台阶修好。
