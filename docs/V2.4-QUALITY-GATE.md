# V2.4 Stage 04 Quality Gate

## Formal scope

V2.4 正式建设 Stage 04 Debug Hunter。Stage 05～08 仍是 prototype，不纳入本次完成判断。

正式闭环：

```text
Evidence Record
→ Mission Chain
→ Debug Case
→ Evidence Workbench
→ Mixed Challenge
→ Broken Firmware Boss
→ Exit Check
```

## Blocking checks

从仓库根目录运行：

```powershell
node --check tools/validate-content.mjs
node tools/validate-content.mjs
```

质量检查必须阻断以下问题：

- Stage 04 Mission 缺少 Predict、Action/Observe、Break It、Debug 或 Transfer/Exit；
- Stage 04 Debug Case 缺少 Evidence、Hypotheses、Experiments、Root Cause、Fix 或 Verification；
- Stage 04 Mixed Challenge、Exit Check、Workbench 或 Boss Fixture 路径不存在；
- Boss 的五个 Evidence Pack 路径不存在；
- HTML Lab 缺少 doctype、lang、viewport、共享基础样式或状态反馈；
- 在本页 Final gate 尚未满足前，当前状态文档不得把 V2.4 写成已完成，或把 Stage 04 prototype 当成已完成版本；
- 内部 Markdown 链接断裂。

其他 Stage 的旧 prototype 内容检查仍可作为 advisory，不阻断 V2.4。

## Evidence status vocabulary

每次验收必须明确：

| 状态 | 含义 |
|---|---|
| PC 仿真已验证 | Host Fault Fixture 在本地编译并通过回归 |
| 静态证据已验证 | Markdown、C 代码结构、路径和字段已检查 |
| 浏览器交互已验证 | Workbench 在目标尺寸下操作和控制台检查通过 |
| 真实 MCU / 仪器尚未验证 | 没有连接开发板、Debugger、示波器或逻辑分析仪 |

不能把前三项合并表述成真实硬件验证。

## Browser acceptance

Workbench 必须在：

- 1280×800；
- 375×812；

下满足：

- 无整体横向溢出；
- Tab、Select、Button、Textarea 可键盘操作；
- ``:focus-visible`` 清晰可见；
- 动态反馈有 ``role="status"`` 和 ``aria-live``；
- 浏览器控制台无 JavaScript 错误；
- Fault Scene、Watchpoint、Instrument Selection 和 Evidence Record 均可操作。

## Host fixture acceptance

有 C 编译器时：

```powershell
cc -std=c11 -Wall -Wextra -pedantic firmware/broken_firmware.c firmware/test_broken_firmware.c -o firmware/stage04-fixture
./firmware/stage04-fixture
```

预期输出：

```text
Stage 04 host fixture regression: PASS
```

没有 C 编译器时只报告静态确认，不能声称 Host Fixture 已运行。

## Final gate

只有以下条件全部满足，``09-Progress/Current.md`` 才能把 V2.4 Stage 04 标记为 completed：

- 三个 Mission 完成闭环；
- 三个 Stage 04 Case 字段完整；
- Mixed Challenge 可独立完成；
- Workbench 浏览器验收通过；
- Boss Fixture 编译/静态检查结果已记录；
- Exit Check 可从 Stage 04 入口进入；
- README、ROADMAP、PROJECT、Current 和 Development Plan 状态一致；
- 没有真实硬件验证被误报为已完成。
