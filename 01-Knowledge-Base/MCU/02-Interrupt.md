# Interrupt — CPU 为什么会停下手里的事？

## 先用一句人话理解

Interrupt（中断）可以理解成：CPU 原本正在做自己的事，某个硬件突然“举手报告”，CPU 暂时停下当前工作，先去处理这个紧急事件，处理完再回来继续。

最直观的例子是按键：如果没有中断，CPU 可能要不停检查“按键按了吗？按了吗？按了吗？”，这种方式叫 Polling（轮询）。有了中断，按键真正发生变化时，硬件可以主动通知 CPU。

```text
Main Program 正在运行
        ↓
Button / Timer / UART 等硬件事件发生
        ↓
Interrupt Request
        ↓
CPU 暂停当前执行
        ↓
ISR 处理中断
        ↓
回到原来的程序位置继续执行
```

## ISR 是什么

ISR 是 Interrupt Service Routine，中断服务程序。它就是“中断发生后 CPU 临时去执行的那段处理代码”。

可以把 ISR 想成值班人员接到报警后执行的应急步骤：处理必须明确、快速，不适合在里面做特别耗时的工作。

## 为什么需要 Priority

如果两个中断几乎同时发生，CPU 需要知道哪个更重要。Priority（优先级）就是这套排序规则。

第一次学习只要建立一个概念：优先级不是“程序快慢”，而是多个中断竞争 CPU 时谁更先得到处理。

## 为什么 ISR 通常要短

ISR 占着 CPU 时，普通程序和其他低优先级工作可能暂时不能运行。ISR 越长，系统越容易出现延迟、丢事件和时序问题。

常见设计是：ISR 只做最必要的事情，比如读取状态、取走数据、发一个事件，再让主循环或 RTOS Task 做后续复杂处理。

## 和变量有什么关系

ISR 和主程序可能同时访问同一个变量，所以会出现共享数据问题。`volatile` 可以提醒编译器不要错误缓存某些会被异步改变的值，但它并不能自动解决原子性、竞争或线程安全。

## 推荐互动

后续使用 CPU / RTOS Timeline 观察：主程序什么时候被打断、ISR 执行多久、多个中断同时发生时优先级如何影响顺序。

## 故障视角

常见现象包括：中断根本不进、中断疯狂重复进入、事件丢失、主程序状态异常、优先级配置导致系统响应异常。
