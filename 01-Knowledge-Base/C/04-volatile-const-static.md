# volatile、const 与 static — 三个看起来像修饰词、实际会改变程序含义的关键词

## 先说为什么要学它们

初学 C 时，你很容易形成一种直觉：

> 变量只有我的代码主动修改时才会变化。

但进入嵌入式以后，这个假设经常不成立。

例如：

```text
硬件寄存器自己变化
中断服务程序修改状态
另一个执行上下文修改共享数据
```

所以程序不仅要表达“这个值是多少”，还要表达“这个对象允许怎样被访问、活多久、谁能看见它”。

`volatile`、`const`、`static` 就是在帮助代码表达这些规则。

---

## volatile — 这个值可能在你没看见的时候变

先看一个直觉场景：

```c
while (ready == 0)
{
    // 等待某件事发生
}
```

如果 `ready` 可能被硬件或 ISR（Interrupt Service Routine，中断服务程序）修改，那么主程序不能简单假设“既然这段循环里没人改 ready，它就永远不变”。

`volatile` 用来告诉编译器：

> 这个对象可能被当前可见代码流之外的因素改变，对它的访问不能随意按照“它不会变”来优化掉。

例如：

```c
volatile int ready;
```

### 常见场景

- Memory-mapped hardware register；
- ISR 与主流程共享的简单状态；
- 某些由外部环境改变的对象。

### 非常重要：volatile 不是什么

`volatile` **不等于线程安全**，也不会自动提供：

- 原子操作；
- Mutex；
- 多核内存同步；
- 正确的 RTOS 任务同步。

它解决的是“访问不能被错误地当成稳定普通变量优化”这一类问题，不是所有并发问题的万能答案。

---

## const — 通过这个接口，不应该修改它

```c
const int max_speed = 100;
```

可以先把 `const` 理解成给代码加一个约束：

> 这个对象通过当前表达式/接口应该被当作只读。

它的价值不只是“防止手滑”，还可以让函数接口更明确。

例如：

```c
void print_buffer(const char *data);
```

这告诉调用者：这个函数接收数据，但不应该通过 `data` 去修改它。

---

## static — 这个名字/对象的生命周期或可见范围不同

`static` 最容易混淆，因为它放在不同位置含义不同。

### 函数内部

```c
void tick(void)
{
    static int count = 0;
    count++;
}
```

普通局部变量通常每次进入函数都会重新创建，而这个 `count` 会在多次函数调用之间保留状态。

### 文件作用域

```c
static int internal_state;
```

这里常用来限制这个名称只在当前源文件内部使用，减少模块之间互相碰到内部实现细节。

---

## 三个词先这样区分

```text
volatile → 它可能在你看不见的地方变化
const    → 通过这里不应该改
static   → 生命周期 / 可见范围发生变化
```

这只是第一层直觉，后续遇到更复杂的 C 语言规则时再逐步补充。

## 推荐学习方式

不要背定义。分别问三个问题：

1. 去掉这个关键词，程序或编译器可能做出什么不同选择？
2. 这个关键词是在描述“值”、 “访问规则”还是“生命周期/可见性”？
3. 它以后为什么会出现在硬件寄存器、ISR、模块接口里？
