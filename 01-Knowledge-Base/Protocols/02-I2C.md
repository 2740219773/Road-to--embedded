# I²C — 两根线为什么能挂很多设备

## 先用一句人话理解

I²C（Inter-Integrated Circuit）是一种让一个 Controller（通常是 MCU）通过两根共享信号线和多个设备通信的总线。

最小结构：

```text
MCU / Controller
    │
    ├── SDA ───────── Sensor 0x48
    │        ├──────── EEPROM 0x50
    │        └──────── RTC    0x68
    │
    └── SCL ───────── 同一组设备
```

- SDA：Serial Data，数据线；
- SCL：Serial Clock，时钟线；
- Address：设备在同一条总线上的编号。

可以先把它想成一间教室：所有设备都接在同一组线上，Controller 先叫 Address，被叫到的设备才应该回应。

## I²C 在系统哪里

Stage 02 已经建立：

```text
Code
→ Peripheral
→ Pin
→ Voltage
```

I²C 在这条链上增加了“共享总线”和“协议响应”：

```text
Application wants register data
↓
I²C Controller / Driver
↓
SDA / SCL Pins
↓
Electrical Bus
↓
Address / ACK / Data transaction
↓
External Device
```

所以看到 `NACK` 时，不能只盯着地址。NACK 只是“当前事务没有得到确认”的现象，原因可能在软件、地址、电气、供电或设备状态。

## 为什么只有两根线还能挂很多设备

因为 SDA / SCL 是共享的 Bus（总线）。

Controller 在一次事务开始时发送 Address：

```text
START
→ Address
→ R/W
→ ACK
→ Data...
→ STOP
```

只有 Address 匹配并且设备愿意响应时，目标设备才会在 ACK 位把 SDA 拉低表示确认。

## Open-Drain 是什么

I²C 的一个关键特点是：很多节点不会主动把 SDA/SCL 强推到 High，而是主要负责把线路拉 Low。

这种输出方式常叫 Open-Drain（开漏）。

可以把它理解成：

```text
Device wants LOW  → actively pull line down
Device wants HIGH → release line
Pull-up resistor  → brings released line back HIGH
```

这就是为什么 Pull-up（上拉电阻）对 I²C 很重要。

## 为什么没有 Pull-up，总线可能根本不成立

正常空闲时，SDA 和 SCL 一般应保持 High。

如果没有合适的 Pull-up：

```text
device releases line
↓
line cannot reliably return HIGH
↓
START / STOP / bit timing all lose meaning
```

这时继续分析 Address 是否正确没有太大价值，因为物理层条件都还没满足。

所以 I²C 调试的第一条重要原则是：

> 先确认 SDA/SCL 能形成合法 HIGH/LOW，再解释协议字节。

## 7-bit Address 和 Address Byte 不是同一个数字

这是新手非常容易混淆的地方。

假设 Datasheet 写：

```text
7-bit device address = 0x50
```

总线上第一次发送的 Address Byte 通常还要加上 R/W bit：

```text
Address Byte = (7-bit Address << 1) | R/W
```

所以：

```text
Write: 0x50 << 1 | 0 = 0xA0
Read : 0x50 << 1 | 1 = 0xA1
```

这不代表设备地址有三个值。

正确理解是：

```text
Device identity = 0x50 (7-bit)
On-wire write address byte = 0xA0
On-wire read  address byte = 0xA1
```

不同驱动/API 对传入参数的要求可能不同：有的要 7-bit Address，有的接口可能要求已经左移后的形式。

因此不要靠猜，必须确认 API contract。

## ACK / NACK 是什么

ACK（Acknowledge）可以先理解成：

> 接收方在这个字节后回答“收到，并且我愿意继续”。

NACK（Not Acknowledge）则表示没有确认。

Address NACK 可能来自：

- 设备地址不匹配；
- 设备没有供电；
- 设备尚未 ready；
- SDA/SCL 电气条件有问题；
- 地址格式被 API 左移/未左移错了一位；
- 设备状态不允许当前操作；
- 时序超出器件能力。

所以：

```text
NACK
≠
一定是 Address 写错
```

## START 和 STOP 是什么

I²C 的 START / STOP 不是额外的第三根线，而是 SDA 在 SCL 为 High 时发生特定变化形成的总线条件。

初学阶段不必先背所有时序细节，只需要知道逻辑分析仪或示波器能帮助你回答：

```text
Bus idle 正常吗？
START 真的出现了吗？
Address Byte 是什么？
ACK 位是谁拉的？
STOP 有没有出现？
```

## 为什么 I²C 要同时看软件和波形

软件层可能告诉你：

```text
Transmit address 0x50
```

但真正重要的是继续验证：

```text
SDA/SCL idle voltage
→ START
→ on-wire address byte
→ R/W bit
→ ACK / NACK
```

如果逻辑分析仪显示线上实际 Address Byte 根本不是你期望的值，就应该回去检查 7-bit / shifted address 的理解和 API 使用方式。

如果线上 Address 正确，但 SDA/SCL 空闲电平只有 0.2 V / 0.1 V，那么优先修物理总线，而不是继续改地址。

## I²C Bus Visualizer

进入：[I²C Bus Visualizer](../../03-Interactive-Labs/I2C-Bus-Visualizer/README.md)

推荐依次实验：

```text
1. Device 0x50 / Master 0x50 / Power ON / Pull-up ON
2. Master 改成 0x51
3. 地址恢复，关闭 Device Power
4. Power 恢复，关闭 Pull-up
5. Read / Write 切换，观察 Address Byte 0xA0 / 0xA1
```

重点不是记结果，而是区分每种失败发生在哪一层。

## 真机最小学习顺序

建议：

```text
1. 查 Datasheet：设备 7-bit Address 是多少
2. 查 Schematic：SDA/SCL 接哪两个 Pin，Pull-up 在哪里
3. 上电后测 SDA/SCL 空闲电平
4. 用逻辑分析仪确认 START / Address / ACK
5. 先完成一次最小写或读
6. 再进入寄存器地址 / Data 含义
7. 最后故意制造错误地址、断电、缺 Pull-up 等故障
```

不要第一步就写完整传感器驱动。

## 常见 No ACK 调查顺序

```text
Device VCC / GND correct?
↓
SDA / SCL idle HIGH?
↓
Pull-up present and appropriate?
↓
Correct pins / Alternate Function?
↓
START appears?
↓
7-bit Address meaning correct?
↓
On-wire Address Byte correct?
↓
ACK bit present?
↓
Device ready / timing / state correct?
```
