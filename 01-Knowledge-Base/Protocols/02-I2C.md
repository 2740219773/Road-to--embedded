# I²C — 两根线为什么能挂很多设备

## 先用一句人话理解

I²C（Inter-Integrated Circuit）是一种让 MCU 和多个小芯片“在同一组两根信号线上轮流说话”的通信方式。

例如一块开发板上可能同时有温度传感器、EEPROM、时钟芯片。它们不一定每个都单独占两根通信线，而是可以一起连接到同一条 I²C Bus（总线）上，再靠 Address（地址）区分“这句话是说给谁听的”。

```text
             ┌→ Temperature Sensor 0x48
MCU ─ SDA/SCL ┼→ EEPROM            0x50
             └→ RTC               0x68
```

SDA 是数据线，负责传数据；SCL 是时钟线，负责告诉大家什么时候读取这一位数据。

可以把它想成一间教室：所有人都能听见老师说话，但老师先喊名字（Address），被叫到的设备才回答。

## 第一次需要认识的几个词

- Bus：多台设备共享的一组线路；
- Address：设备在这条总线上的编号；
- START / STOP：一次交流开始和结束的标志；
- ACK：接收方回答“我收到了”；
- NACK：没有确认，可能是设备没响应，也可能有其他问题；
- Pull-up：上拉电阻，让没人主动拉低线路时，SDA/SCL 能回到高电平；
- Open-Drain：设备主要负责把线拉低，而高电平通常由上拉电阻形成。

先不用背这些词。第一次学习只需要建立三个概念：两根线、设备有地址、接收方会确认。

## 一次最小通信

```text
START → Address → R/W → ACK → Data → ACK → STOP
```

R/W 表示这次是读还是写。

## 为什么工程上不能只看软件

I²C 不只是“发几个字节”。如果上拉电阻缺失、设备没供电、SDA/SCL 被拉死，即使程序里的地址完全正确，也不会形成正常通信。

因此遇到 NACK 时，不要马上换驱动代码。先问：设备有没有电？两根线空闲时是不是高电平？地址有没有真的出现在波形里？
