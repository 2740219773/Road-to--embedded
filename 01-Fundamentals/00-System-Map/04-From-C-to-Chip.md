# 04 — 一段 C 代码是怎么跑到芯片上的

## 学习目标

完成这一课后，你应该理解：

- `.c` 文件不是芯片直接执行的东西；
- 编译、汇编、链接分别在做什么；
- ELF / HEX / BIN 大致是什么；
- “烧录程序”本质上发生了什么；
- 为什么嵌入式开发经常需要看编译器、链接脚本和启动文件。

---

## 1. 从 C 代码开始

例如：

```c
int main(void)
{
    int a = 1;
    int b = 2;
    int c = a + b;

    while (1)
    {
    }
}
```

MCU 并不能直接理解这些字符。

CPU 真正能够执行的是机器指令。

因此需要工具链完成转换。

---

## 2. 一个简化的软件构建过程

```text
main.c
  ↓
预处理
  ↓
编译
  ↓
汇编
  ↓
目标文件 .o
  ↓
链接
  ↓
ELF
  ↓
转换
  ↓
HEX / BIN
  ↓
烧录
  ↓
MCU Flash
```

现在只需要先理解整体流程，不需要记住所有细节。

---

## 3. 预处理

预处理器主要处理类似：

```c
#include <stdio.h>
#define LED_PIN 5
#ifdef DEBUG
```

也就是说，很多以 `#` 开头的内容会在真正编译之前先处理。

---

## 4. 编译

编译器把 C 语言转换成更接近 CPU 的形式。

例如：

```c
c = a + b;
```

最终会变成对应目标 CPU 架构的指令。

ARM、x86、RISC-V 使用的机器指令并不一样，所以嵌入式开发经常需要“交叉编译器”。

---

## 5. 什么是交叉编译

假设你在 Windows PC 上开发 STM32：

```text
开发机器：x86 / x64 PC
目标机器：ARM Cortex-M MCU
```

你不能让普通 PC 编译器生成 x86 程序后再塞进 STM32。

必须使用能在 PC 上运行、但生成 ARM 指令的编译器。

这就叫 Cross Compilation（交叉编译）。

---

## 6. 链接

一个真实工程通常不只有 `main.c`：

```text
main.c
uart.c
gpio.c
timer.c
protocol.c
```

每个文件会先形成自己的目标文件，最后由链接器把它们组合起来。

链接器还必须决定：

```text
代码放 Flash 哪个位置？
变量放 RAM 哪个位置？
中断向量表放哪里？
栈多大？
堆多大？
```

这些信息通常和 Linker Script（链接脚本）有关。

这也是嵌入式和普通上位机开发一个非常明显的区别：你会越来越关心程序在物理内存中的位置。

---

## 7. ELF、HEX、BIN

### ELF

ELF 通常包含的信息最多，例如：

- 程序代码；
- 数据；
- 符号信息；
- 调试信息。

调试器经常使用 ELF。

### BIN

BIN 更接近纯二进制镜像。

可以简单理解为：

> 最终需要写入存储器的一串字节。

### HEX

HEX 使用文本格式保存地址和数据，在 MCU 工具链里也非常常见。

前期不用纠结格式细节，只需要知道它们用途不同。

---

## 8. 烧录到底是什么

所谓“下载程序”或者“烧录固件”，本质上就是：

> 通过调试器或 Bootloader，把编译生成的数据写进 MCU 的 Flash。

例如常见方式：

```text
PC
 ↓ USB
ST-Link / J-Link
 ↓ SWD / JTAG
MCU
 ↓
内部 Flash
```

重新上电后，CPU 从规定的启动地址开始取指令并执行。

---

## 9. Reset 后发生什么

简化理解：

```text
芯片复位
  ↓
读取启动地址
  ↓
建立栈
  ↓
初始化 RAM 数据
  ↓
初始化运行环境
  ↓
进入 main()
```

所以实际上 CPU 并不是复位后直接神奇地跳到 `main()`。

在 `main()` 之前通常还有 Startup Code（启动代码）。

以后看到：

```text
startup_stm32xxxx.s
system_stm32xxxx.c
*.ld
```

不要把它们当成“神秘文件”。它们都属于这条启动链路的一部分。

---

## 10. 为什么现在就要知道这些

以后遇到下面这些问题时，你会回到这一课：

- 程序 Flash 超限；
- RAM 不够；
- HardFault；
- 全局变量初始化异常；
- Bootloader 跳转失败；
- 中断向量表地址错误；
- 编译成功但链接失败；
- Debug 和 Release 行为不同。

这些问题很多都不是“业务代码写错了”，而是程序构建和运行机制的问题。

## 完成标准

能用自己的话讲清楚下面这条链：

```text
源代码
→ 编译
→ 链接
→ 固件
→ 烧录
→ Flash
→ Reset
→ Startup
→ main()
```

做到这一点，Phase 0 的第一轮系统地图就基本建立起来了。
