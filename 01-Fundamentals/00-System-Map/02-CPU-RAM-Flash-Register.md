# 02 — CPU、RAM、Flash、寄存器到底是什么

## 学习目标

完成这一课后，你应该理解：

- CPU 在做什么；
- RAM 和 Flash 为什么都需要；
- 寄存器为什么是嵌入式开发的核心概念；
- 为什么“写一个寄存器”就能控制 GPIO、串口、定时器等硬件。

---

## 1. CPU：负责执行指令

CPU 可以先简单理解成“执行程序的核心”。

它不断重复类似过程：

```text
取指令 → 解析指令 → 执行指令 → 取下一条指令
```

例如 C 代码：

```c
c = a + b;
```

最终会被编译器转换成 CPU 能执行的机器指令。

嵌入式开发里，我们写的是 C，但真正执行的是 CPU 指令。

---

## 2. Flash：断电后仍然保存程序

Flash 是非易失性存储器。

“非易失性”的意思是：

> 断电之后内容不会消失。

MCU 程序通常烧录到 Flash 中。

可以先把它理解成设备里的“系统盘”。

里面可能保存：

- 程序代码；
- 常量；
- 固件版本；
- 一些需要长期保存的配置。

---

## 3. RAM：程序运行时的工作空间

RAM 的特点是：

- 速度快；
- 可以频繁读写；
- 断电通常丢失内容。

运行中的变量、栈、缓冲区通常会放在 RAM 中。

例如：

```c
int temperature = 25;
```

程序运行时，这个变量通常会占用 RAM。

可以把 RAM 理解为“工作台”。

Flash 像仓库，RAM 像正在工作的桌面。

---

## 4. 寄存器：软件控制硬件的关键接口

嵌入式里最重要的概念之一就是寄存器。

这里说的很多“外设寄存器”，可以简单理解成：

> 芯片内部被赋予特殊硬件意义的一组地址。

例如某个地址可能对应 GPIO 输出寄存器。

程序向这个地址写入某些位：

```text
0000 0001
```

硬件电路就可能把某个引脚拉高。

于是出现一条非常重要的链路：

```text
C 代码
  ↓
访问某个内存地址
  ↓
写入寄存器
  ↓
芯片内部数字电路状态改变
  ↓
引脚输出变化
```

这就是“软件控制硬件”的本质之一。

---

## 5. 为什么寄存器经常按位控制

一个 32 位寄存器通常不会只表示一个开关。

例如：

```text
Bit 0   使能
Bit 1   中断使能
Bit 2-3 工作模式
Bit 4   状态标志
...
```

因此嵌入式 C 中会大量使用位运算：

```c
reg |= (1 << 3);      // 置位
reg &= ~(1 << 3);     // 清零
```

所以后面学习 C 语言时，位运算不是考试知识，而是真正的硬件控制工具。

---

## 6. 内存映射外设

很多 MCU 使用 Memory-Mapped I/O（内存映射 I/O）。

也就是说：

```text
普通 RAM              某段地址
Flash                 某段地址
GPIO 寄存器           某段地址
UART 寄存器           某段地址
Timer 寄存器          某段地址
```

CPU 都通过“地址”访问。

区别只在于这个地址背后连接的是 RAM，还是某个硬件模块。

这个概念理解以后，再看 STM32 的寄存器地址、数据手册和 HAL 库，会容易很多。

---

## 7. 一个简化例子

假设：

```text
0x40020014
```

对应 GPIO 的输出数据寄存器。

如果程序做：

```c
*(volatile unsigned int *)0x40020014 |= (1 << 5);
```

可以暂时把它理解为：

> 找到 GPIO 对应的控制地址，把第 5 位设为 1。

最终可能导致某个物理引脚输出高电平。

现在不需要完全理解这行 C 代码，后面学指针和 `volatile` 时会回来拆解。
