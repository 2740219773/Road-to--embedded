# 03 — 裸机、RTOS、Linux 有什么区别

## 学习目标

完成这一课后，你应该理解：

- 什么叫裸机程序；
- RTOS 解决了什么问题；
- Linux 为什么更复杂；
- 三者不是“谁高级谁就一定更好”，而是适用场景不同。

---

## 1. 裸机程序

裸机（Bare Metal）不是指“没有代码”，而是指：

> 程序直接运行在硬件上，中间没有通用操作系统负责调度和资源管理。

一个很典型的结构：

```c
int main(void)
{
    hardware_init();

    while (1)
    {
        read_sensor();
        control_output();
        communicate();
    }
}
```

这种方式非常直观。

### 优点

- 简单；
- 启动快；
- 占资源少；
- 行为容易控制；
- 适合功能较少的小系统。

### 问题

当功能越来越多时：

```text
采集
通信
控制
显示
故障处理
数据保存
协议解析
```

全部塞进一个循环后，程序会越来越难管理。

---

## 2. 中断让裸机系统拥有实时响应能力

真实 MCU 程序不会只是一个死循环。

例如串口来了一个字节，不可能一直等着它。

硬件可以产生中断：

```text
主程序正在运行
     ↓
串口收到数据
     ↓
产生中断
     ↓
CPU 暂停当前工作
     ↓
执行串口中断处理
     ↓
返回原来的程序
```

这也是后续学习 MCU 时非常核心的机制。

---

## 3. RTOS 是什么

RTOS：Real-Time Operating System，实时操作系统。

常见：

- FreeRTOS；
- RT-Thread；
- Zephyr；
- ThreadX。

RTOS 最重要的作用之一是：

> 把一个复杂系统拆成多个任务，并由调度器安排它们运行。

例如：

```text
Task 1：采集传感器
Task 2：处理 Modbus
Task 3：设备控制
Task 4：故障检测
Task 5：状态上报
```

这样代码结构会比一个巨大的 `while(1)` 清晰很多。

---

## 4. “实时”不等于“运行得快”

这是一个非常重要的概念。

实时系统强调的是：

> 在规定时间内做出确定响应。

例如要求：

```text
发生故障后 100 μs 内必须关断输出
```

如果系统有时 10 μs 响应，有时 5 ms 响应，那么即使平均速度很快，也不能说满足这个实时要求。

所以实时更强调：

- 确定性；
- 最大响应时间；
- 优先级；
- 调度行为。

---

## 5. Linux

嵌入式 Linux 通常运行在性能更强的 MPU / SoC 上。

它提供：

- 进程；
- 虚拟内存；
- 文件系统；
- 网络协议栈；
- 用户权限；
- 驱动模型；
- 大量成熟软件库。

一个 Linux 设备可能运行：

```text
Web 服务
数据库
设备控制程序
网络服务
日志程序
GUI
远程升级服务
```

这已经很接近 PC 软件系统。

---

## 6. 三者如何选择

### 裸机更适合

- 简单控制器；
- 功能较少；
- 资源非常有限；
- 对启动速度和确定性要求高。

### RTOS 更适合

- MCU 系统开始复杂；
- 多任务；
- 多通信接口；
- 对实时性有要求；
- 又不需要完整 Linux。

### Linux 更适合

- 网络功能复杂；
- GUI；
- 文件系统；
- 大量数据管理；
- 多进程应用；
- 需要成熟软件生态。

---

## 7. 真实设备可能三者同时存在

例如一台复杂测试设备：

```text
Linux SoC
负责：网络、界面、文件、系统管理
        ↓
MCU + RTOS
负责：实时控制、设备状态、通信
        ↓
FPGA
负责：高速采集、精确定时、并行处理
```

因此未来不要把它们看成互斥路线，而应该理解每一层的职责。

---

## 动手练习

判断下面场景更适合裸机、RTOS 还是 Linux，并说明原因：

1. 一个只读取温度并控制风扇的小板；
2. 一个同时管理 CAN、Ethernet、传感器和电机的控制器；
3. 一个带网页管理、文件存储和远程升级功能的工业网关。

---

## 完成标准

你应该能解释：

- 裸机程序为什么也可以处理中断；
- RTOS 为什么不是简单地“让程序同时运行”；
- 实时为什么不等于快；
- Linux 和 RTOS 最大的应用场景区别。
