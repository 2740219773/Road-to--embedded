# 08 — 编译、链接与内存布局

这一课的目标不是学习编译器理论，而是让你以后看到嵌入式构建错误时知道问题发生在哪一层。

## 从源码到程序

可以先记住：

```text
.c 源文件
  ↓ 预处理
  ↓ 编译
  ↓ 汇编
目标文件 .o
  ↓ 链接
可执行文件 / ELF
  ↓ 转换
.bin / .hex
  ↓ 烧录
MCU Flash
```

## 编译错误与链接错误

### 编译错误

通常当前源文件本身就无法正确转换，例如：

- 语法错误；
- 类型错误；
- 未声明标识符。

### 链接错误

每个文件可能都能单独编译，但最终拼起来找不到实现或出现重复定义，例如：

```text
undefined reference
multiple definition
```

这两类错误的排查思路不同。

## 内存布局先建立模型

典型程序可以先粗略理解为：

- `.text`：程序代码；
- `.rodata`：只读常量；
- `.data`：已初始化全局/静态变量；
- `.bss`：未显式初始化或零初始化的全局/静态变量；
- heap：动态分配；
- stack：函数调用、局部变量等。

不同平台细节会不同，先掌握模型。

## 为什么嵌入式特别关心这些？

因为 MCU 的 Flash 和 RAM 都有限。

以后会遇到：

- 固件放不进 Flash；
- RAM 不够；
- 任务栈溢出；
- 大数组放错位置；
- Bootloader 与 App 地址划分；
- linker script / scatter file。

## 练习

故意制造两类错误：

1. 写一个明显的 C 语法错误，观察编译器提示；
2. 在头文件声明一个函数但不给实现，然后调用它，观察链接阶段提示。

## 完成标准

以后看到构建失败时，第一反应不是笼统地说“编译失败”，而是先判断：

> 是预处理/编译问题，还是链接问题？
