# 02 — 指针与硬件访问

## 核心认识

指针不是为了增加 C 语言难度而存在。它解决的是：**保存和使用地址。**

```c
int value = 10;
int *p = &value;
```

这里：

- `value` 是数据；
- `&value` 得到数据所在地址；
- `p` 保存这个地址；
- `*p` 表示访问这个地址指向的数据。

## 最小实验

```c
#include <stdio.h>

int main(void)
{
    int value = 10;
    int *p = &value;

    printf("value = %d\n", value);
    printf("&value = %p\n", (void *)&value);
    printf("p = %p\n", (void *)p);
    printf("*p = %d\n", *p);

    *p = 20;
    printf("value after change = %d\n", value);

    return 0;
}
```

重点观察：没有直接给 `value` 赋值，为什么它仍然变成了 20？

## 联系 MCU

假设芯片手册规定某硬件寄存器位于：

```text
0x40020014
```

C 程序要访问这个位置，就需要把这个数字解释成地址，再通过指针访问该地址。

这就是以后大量寄存器代码的基础。

## 必须掌握

- `&` 取地址；
- `*` 解引用；
- 指针变量本身也占内存；
- 指针类型为什么重要；
- 空指针概念；
- 指针与数组之间的基本关系；
- 不合法地址为什么可能导致程序崩溃。

暂时不要深入复杂的多级指针技巧。

## 故障练习

阅读下面代码，不要运行：

```c
int *p = (int *)0x12345678;
*p = 100;
```

思考：语法可能没有问题，为什么程序仍可能崩溃？

这正是嵌入式调试中很重要的一类问题：**代码语法正确，不代表访问的硬件地址正确。**

## 完成标准

看到：

```c
*(volatile unsigned int *)0x40020014
```

即使暂时不理解 `volatile`，也能够解释其中“地址 → 指针 → 解引用访问”的过程。
